# Утверждённый интерфейс Veilor

Работаем только с вариантом **«Лента»**. Сохранённый [HTML-макет](mockups/veilor-windows.html) — демонстрация UI со сценариями, не VPN-клиент и не источник реальных данных аккаунта. Текстовые требования ниже имеют приоритет при расхождении старых вариантов.

- Логотип veilor кликабелен и открывает https://sigmagate.link/. Рядом «Поделиться», пока открывает тот же сайт, и настройки.
- Вместо «Текущая конфигурация»/«Основное подключение» — почта пользователя и срок подписки. Счётчик гигабайтов убран.
- Подключение — большой toggle без отдельной подписи «Включено/Выключено». Лишние тексты «Ваше подключение», «Не подключено», «Выберите сервер и подключитесь» не нужны.
- Компактный переключатель «Игровой / Рабочий». На этапе согласования это только новые названия для «Правила / Глобально», без обещания оптимизации игр или работы.
- Сразу под режимами — компактный ряд: память, время подключения, количество соединений. Ряд строго по центру и по ширине переключателя режимов, независимо от ширины окна. Счётчик соединений — кнопка; зелёный при подключении, красный при ошибке, серый при отключении. В макете цвет можно менять кликом; в приложении он должен отражать настоящий state.
- Ниже — флаг страны и IP. Зелёный при подключении, красный при отключении, без ON/OFF и без «Ваш IP». Флаги, а не буквенные RU/BE.
- Выбор сервера с текущим названием/задержкой остаётся доступным.
- «Оплатить» выше ряда маленьких кнопок. Без автоподписки активна; с автоподпиской неактивна и показывает дату автоплатежа. Реальных MySQL/панель/API данных пока нет; не выдумывать endpoint и не соединять мобильный клиент напрямую с MySQL. PHP API — отдельная задача после получения данных.
- Компактные серые кнопки «Скорость» (Speedtest) и «Обновить». Обновление объединяет обновление информации подписки/трафика и конфигурации, но эти два результата остаются отдельными: возможен частичный успех. Поведение не должно терять текущие рабочие данные при ошибке.
- Ошибки подключения и истёкшая подписка: заголовок и описание по центру. «Подробнее» — настоящая кнопка по центру; «Оплатить» в этом состоянии не должна растягиваться на всю подложку.
- Остальной функционал перенести в отдельный пункт расширенных настроек. Финальная карта соответствия Karing/OneXray ещё не составлена; нельзя объявлять весь функционал идентичным только по виду главного экрана.

Макет сохранён из Karing-архива `2ddb6b52:docs/veilor/mockups/veilor-windows.html` без переписывания дизайна. Текущие mock actions и данные user@example.com/примерные даты не являются продуктовой реализацией. В Flutter сохранять узкое центральное выравнивание и проверить длинные русские тексты/размеры окна на реальной сборке.
