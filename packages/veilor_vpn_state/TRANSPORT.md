# Связь транспорта и состояний VPN

22 октября 2026. Добавлен чистый reducer `lib/transport_bridge.dart` и лабораторный адаптер `../veilor_core_transport_lab/lib/lab_vpn_controller.dart`. UI и реальное ядро к ним пока не подключены. Числовые значения нативных состояний и wire-контракт отсутствующего Flutter-пакета не выдумывались.

## Два разных состояния

TransportStage отражает жизненный цикл **своего** процесса; VpnSnapshot отражает только подтверждённое состояние VPN. Это не детектор всех VPN в системе и не состояние установленного Karing.

| Событие | TransportStage / операция | Состояние VPN |
| --- | --- | --- |
| Начало запуска | starting, busy | unknown; зелёного индикатора и таймера нет |
| TCP-уведомление и проверенный управляющий порт | ready | Остаётся unknown |
| Начало reload | ready, reloading | Предыдущее connected теряет подтверждение |
| Успешный HTTP/JSON reload | ready, операция завершена | Сам по себе connected не создаёт |
| Отказ или таймаут reload | ready, операция завершена | Ошибка operation/timeout; без догадки о disconnected |
| Подтверждённый callback VPN | ready | Только этот источник может установить connected и разрешить таймер |
| Начало stop | stopping, busy | Подтверждение connected снимается, поздний reload игнорируется |
| Выход процесса после stop и очистка ресурсов | stopped | Остаётся unknown; принудительная остановка отмечается ошибкой |
| Неожиданный выход процесса | failed | unknown + serviceExit; зелёный индикатор и таймер выключены |
| Ошибка подготовки запуска после очистки | failed | unknown + preparation/serviceExit/timeout |

Даже завершение своего процесса не подтверждает восстановление системного proxy/TUN, поэтому состояние disconnected не синтезируется. Для таймера дополнительно по-прежнему нужен актуальный core startTime: мост не запускает собственный счётчик.

`observeVerifiedState` предназначен для будущего адаптера доверенных callback/currentState. В текущем стенде такого источника нет: метод используется только в тестах с явно синтетическими состояниями. До готовности транспорта и при остановке наблюдения не принимаются. Метрики, IP и подписка не служат подтверждением VPN.

## Порядок событий

- У каждого запуска непрозрачный session token. События другого экземпляра или предыдущего запуска отклоняются.
- Reload имеет отдельный command token. Повторное завершение, ответ после stop/exit и ответ предыдущей команды игнорируются.
- Если после начала reload пришёл новый подтверждённый callback, он имеет приоритет над запоздавшим результатом команды.
- Выход процесса сразу снимает подтверждение VPN; новый запуск разрешается после подтверждённого освобождения ресурсов.
- Обычная остановка и неожиданный выход различаются по принятому намерению stop. Принудительное завершение при stop не скрывается.

Лабораторный контроллер подписывается на Future выхода созданного Process, передаёт ошибки запуска/HTTP в reducer и очищает ресурсы после неожиданного выхода. Он публикует неизменяемые снимки через broadcast stream; при подписке сначала нужно читать `snapshot`, stream не воспроизводит прежние события. Повторный start во время запуска/живой сессии отклоняется. Повторные stop/dispose используют один Future. Dispose во время запуска дожидается ограниченной попытки запуска и затем очищает свою сессию; новые команды при закрытии блокируются. Это не мгновенная отмена запуска.

## Проверки

- **14 новых тестов политики**: разделение готовности и VPN, приоритет свежего callback, запоздавшие события, чужие токены, stop во время reload, ошибки и повторный запуск после очистки.
- **11 новых интеграционных тестов контроллера**: реальные синтетические Dart-процессы, таймауты, отказ с последующим выходом, принудительная остановка, dispose при запуске, поздний HTTP-ответ и проверка всех опубликованных статусов на отсутствие выдуманного connected/таймера.
- Прежние **24 теста VpnStateStore** и **22 теста транспорта** проходят. Итого 71 проверка в этих двух пакетах.
- Dart analyzer в обоих пакетах — без замечаний.

# packages/veilor_vpn_state

# packages/veilor_core_transport_lab
dart pub get
dart analyze
dart test/transport_test.dart
