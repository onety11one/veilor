## Основания

В текущем `lib/screens/my_profiles_screen.dart:1742` и `:1761` вызывается отсутствующий `SingboxConfigBuilder.buildOutbound()`. В `lib/app/modules/server_manager.dart:1591` и `:1605` в raw записываются служебные поля профиля.

Исторический `research/karing-vpn-service-reference/lib/app/utils/singbox_config_builder.dart:2066` проверяет наличие Map, заменяет tag актуальным и удаляет только шесть верхнеуровневых полей: `groupid`, `ip`, `attach`, `latency`, `outlet_ip`, `outlet_region`. Остальные параметры протокола сохраняются. Эта логика перенесена с сохранением исходного уведомления об авторстве, см. NOTICE.md.

Публичная текущая реализация метода недоступна. Совпадение проверяется с найденной исторической версией, а не с недостающим текущим генератором.

## Поведение адаптации

- Сохраняет все остальные JSON-поля, в том числе неизвестные новые поля, TLS/transport, detour, null и порядок элементов списков. Вложенные одноимённые поля не удаляются.
- Актуальный tag передаётся явно, пустой tag отклоняется. Профиль без Map отклоняется типизированной ошибкой; старый код в этом случае возвращал null. Будущий вызывающий слой должен обработать отказ, а не молча пропустить сервер.
- Не изменяет исходный raw. Исторический метод менял raw.tag, а DeepCopyUtils копировал Map, но оставлял List общей с оригиналом. Адаптация копирует и карты, и списки; генерация не портит сохранённый профиль.
- Отклоняет не-JSON значения и циклическую/слишком глубокую структуру. Ошибки не содержат raw или параметров доступа.

## Проверка

```powershell
dart run test/projection_test.dart
dart analyze lib test
```

Тест запускается из папки пакета и использует архив исходников внутри этого репозитория. Он извлекает **текст настоящих исторических canBuildOutbound/buildOutbound**, запускает их в отдельном Dart-процессе и сравнивает нормализованный JSON. Тестовая оболочка ProxyConfig содержит только raw/tag; DeepCopyUtils взят из того же исторического commit. Полная историческая Flutter-программа не собирается.

Добавлены синтетический VLESS+TLS+WebSocket профиль и отдельный ожидаемый результат. Адреса `.invalid`, тестовые IP и UUID не используются для сетевого подключения. Ещё пять сравнений покрывают простой direct, поля Shadowsocks, неизвестный тип с дополнительными полями, вложенные одноимённые метаданные и сохранение WireGuard peers. Эти сравнения проверяют перенос JSON, **не работоспособность перечисленных протоколов**.

Дополнительно проверены отсутствие изменений исходника, независимость вложенных списков/карт и повторных результатов, недопустимые входы, пустой tag и цикл.

21 октября 2026, Windows, Dart 3.12.2: **14 тестов прошли, включая 6 сравнений с исполняемым историческим кодом**; итоговый анализатор — **No issues found**.

## Граница результата и продолжение

Результат — **фрагмент outbound**, не готовый service_core.json. Проверка JSON и совпадения фрагмента не подтверждает принятие конфигурации ядром. В частности, WireGuard в текущем генераторе проходит отдельный этап `endpoints()`; этот шаг здесь ещё не реализован.

Полный минимальный конфиг пока не выдаётся: старые DNS-модели несовместимы с текущими вызовами, а выдумывать значения или подменять режимы нельзя. Исходники активного приложения, установленный Karing и пользовательские профили не менялись; сетевых тестов сервера не было.

Добавлены [минимальный типизированный DNS](DNS.md) и [полная тестовая сборка с inbound/route и проверкой официальным ядром](MINIMAL-CONFIG.md). Это отдельные ограниченные контракты; они не заменяют полный генератор и DNS-настройки Karing. Подробности итоговой проверки и её ограничения указаны в отчёте.
