# Veilor: состояние проекта на 22 октября 2026

Полноценная Windows-сборка с работающим VPN ещё не готова. Есть утверждённый UI, изолированные проверенные модули и исследование недостающей обвязки Karing. Цель — сохранить весь функционал, изменив интерфейс. Паритет пока не доказан.

## Интерфейс

Утверждён вариант «Лента». Последующие автоматические события выбора других карточек не заменяют явное утверждение пользователя. Приоритет — Windows.

- Логотип и «Поделиться» открывают https://sigmagate.link/; доступны настройки.
- Почта пользователя, срок подписки, оплата либо неактивная дата автоплатежа. Счётчик гигабайтов убран.
- Большой тоггл подключения, без подписей «Включено/Выключено».
- «Игровой / Рабочий» пока означают прежние «Правила / Глобально», без новой логики маршрутизации.
- Память, время подключения, количество соединений компактно центрируются в общем блоке шириной переключателя; счётчик соединений интерактивен.
- Флаг страны и IP: зелёный при подключении, красный при отключении, без ON/OFF и «Ваш IP».
- Выбор сервера; компактные серые действия скорости/обновления; оплата выше них.
- Общее обновление должно объединять прежние действия обновления данных подписки и конфигурации, с обработкой частичного успеха.
- Тексты ошибок и окончания подписки центрируются; «Подробнее» — отдельная кнопка; оплата в состоянии окончания подписки не растягивается на всю подложку.

Сохранён [интерактивный Windows-макет](mockups/veilor-windows.html). Это демонстрация, а не VPN. Нужны проверка фактической компоновки и интеграция с реальными данными. PHP API подписки/оплаты не подключён: пользователь ещё не передал схему MySQL и данные панели. Прямое подключение Windows-клиента к MySQL не предусмотрено.

## Исходная база и версии

- Репозиторий: onety11one/veilor; upstream KaringX/karing.
- Активная база: 1f52c28e062fe55d7c3ccc254f1a90d53fd8c103, Karing 1.2.26+2908, ожидаемое ядро 1.14.0.
- Исследованный установленный бинарник: Karing 1.2.25+2802, соответствующий публичный source commit 0c320dc182d095ec0d483f852169421e749c2bac.
- Историческая обвязка: e3c19f1eb1225dbd48a4862f0983b82d0af8de69, сохранена в research/karing-vpn-service-reference.
- Публичной базы недостаточно для сборки: отсутствуют актуальные VPN-обвязка и другие необходимые Dart/native-компоненты. Исторические файлы нельзя автоматически считать совместимыми.

Активные lib/bind/windows/pubspec не изменены относительно базы. Новые пакеты пока не подключены к приложению.

## Исследование службы

Найдены аргументы run2/service-config/service-http-port/connected-port, обработчики reload/stop и формы ответов. Разделены служебный HTTP API и Clash API. Из 25 наблюдаемых полей service.json для 9 подтверждены конкретные читатели; обязательность/defaults всей схемы не закрыты.

Подтверждены зависимости от локальных .srs и динамический loader libcronet.dll. Подготовлена раскладка выбранных local rule sets без изменения core JSON. Наборы assets разных версий нельзя смешивать автоматически.

Выявлен singleton по имени exe: копия в другой папке может завершить работающий одноимённый процесс. Поэтому реальный core не запускался, включая --help. Команды stop/reload установленному VPN не отправлялись. Для первого настоящего запуска нужна отдельная Windows VM со снимком состояния.

## Последний результат: карта AOT-методов

Portable MSVC/SDK установлены после разрешения пользователя; собран анализатор Windows x64 под точный Dart 3.12.2 без compressed pointers. Реальный format hash исходников совпал с snapshot без подмены.

Получены 42 записи методов из четырёх выбранных файлов vpn_service. Два успешных запуска дали одинаковые имена/адреса/размеры. Найдены constructor и две записи toJson VpnServiceConfig, методы запуска/остановки/ожидания; три диапазона config дизассемблированы независимо Capstone.

Это метаданные и машинный код, не восстановленный Dart source. Имена полей, defaults, значения параметров и переходы состояний ещё не восстановлены. Отдельный fromJson не обнаружен; inlining/tree shaking не исключены.

Первый запуск анализатора завершился 0xC0000005; после добавления диагностики и пересборки два запуска успешны. Причина первоначального сбоя неизвестна. Загрузка snapshot в VM может выполнять внутренние stubs; её нельзя называть чисто статическим чтением ELF. App main не вызывался, attach к работающим процессам не выполнялся.

## Следующие шаги

1. Сопоставить constructor/toJson с object pool, определить поля/defaults VpnServiceConfig.
2. Восстановить Windows prepare/start/waitConnect/reload/stop и очистку при сбоях, подтвердить источник состояния.
3. Согласовать целевые версии исходников и бинарника; проверить различия перед переносом.
4. Закрыть системные операции: TUN, proxy, маршруты, права, службу, автозапуск.
5. Дополнить генератор: протоколы, DNS, rules, исключения, выбор сервера и настройки оригинала.
6. Испытать настоящий core в изолированной Windows VM: трафик, остановка, сбои, восстановление сети.
7. Подключить UI к backend, затем проверить паритет по каждой функции Karing.
8. Подключить PHP API после получения схемы и доступа; собрать установочный пакет.

## Проблемы и способы решения

| Проблема | Решение / граница |
| --- | --- |
| Нет актуальных исходников обвязки | Восстанавливать по истории, AOT и проверяемому поведению; при тупике писать собственный слой с отдельной проверкой паритета |
| Разные версии source/binary | Зафиксировать целевую версию либо явно проверять различия |
| Неизвестны поля/defaults | Разбор constructor/toJson, затем контролируемые испытания |
| Риск повлиять на действующий VPN | Отдельная VM; другая папка не изолирует singleton |
| Mock не доказывает совместимость | Настоящие испытания после восстановления контракта |
| Нестабильность анализатора | Повторяемость, сохранение результатов, независимое дизассемблирование |
| Нет доказательства полного паритета | Матрица функций и одинаковые сценарии Karing/Veilor |
| Нет данных аккаунта/оплаты | Продолжать с демонстрационными состояниями до подключения API |

Замена ядра на Xray сама по себе не сохранит все функции Karing: соответствующий слой придётся реализовать и проверить.
