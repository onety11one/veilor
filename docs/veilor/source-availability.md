# Доступность исходников для сборки Karing

Проверка 21 октября 2026, база `1f52c28e062fe55d7c3ccc254f1a90d53fd8c103`.

## Подтверждённые препятствия

1. В `pubspec.yaml` явно указан локальный `../vpn-service/`; в `pubspec.lock` версия этого пакета `0.12.15`. Пакета рядом с проектом нет. `git ls-remote https://github.com/KaringX/vpn-service.git HEAD` возвращает `Repository not found`; подключённый GitHub также возвращает 404. Из этих ответов нельзя установить, удалён ли репозиторий или он закрыт для нашего аккаунта.
2. Сканирование `package:karing/` импортов в опубликованных Dart-файлах выявило **66 отсутствующих целей импорта**. Среди них `lib/app/local_services/vpn_service.dart`, `lib/app/utils/path_utils.dart`, множество утилит, `lib/screens/statistics_records_screen.dart` и приватные `app_url_utils_private.dart`, `sentry_utils_private.dart`. Эти файлы отсутствуют в базовом Git-дереве, а не потеряны при нашей доработке. Подробная опись с импортирующими файлами находится во внешнем отчёте `veilor-source-blockers.json`.
3. В рабочем дереве нет `bind/windows/core`. Этот путь исключён из Git исходного проекта. Понадобятся совместимые нативные компоненты и способ их подключения/сборки.

Полный список препятствий сборки пока не исчерпан: успешная установка Flutter сама по себе не исправляет отсутствующие исходники и нативные компоненты. Восстановление отсутствующих утилит и VPN-обвязки по предположениям было бы новой реализацией с неподтверждённым поведением.

## Подтверждение со стороны проекта

- [Issue #1528: запрос доступа к vpn-service](https://github.com/KaringX/karing/issues/1528) описывает недоступность репозитория при локальной сборке. Закрытие issue не предоставляет доступ и не доказывает, что зависимость стала доступной.
- [Issue #1460: отсутствующая зависимость и генерация конфигурации](https://github.com/KaringX/karing/issues/1460) также описывает отсутствие локального пакета и делегирование генерации конфигурации `VPNService`.
- [Issue #603](https://github.com/KaringX/karing/issues/603) содержит ответ участника проекта о статусе vpn-service. Юридические выводы из комментариев в этом отчёте не делаются.

## Что требуется для продолжения именно функциональной сборки

Полный совместимый исходный workspace от разработчиков Karing или доступ к недостающим репозиториям, включая vpn-service, пропущенные файлы приложения и нативные компоненты/инструкции. Нужна фиксация версий относительно нашей базы. Установленный Karing или его готовый EXE не предоставляет отсутствующие Dart-исходники для повторной компиляции изменённого интерфейса.

## Что можно делать независимо

Установить SDK, разрабатывать и тестировать чистые Flutter-компоненты нового UI отдельно от VPN. Это не подтверждает сохранение всех функций Karing и не считается функциональным выпуском Veilor. Исходный pubspec/lock и сетевую логику не подменяем заглушками ради успешной компиляции.

Полную установку Visual Studio C++ целесообразно выполнить после решения вопроса исходников: сейчас она не снимает основной блокирующий фактор. SDK Flutter размещается локально в рабочем каталоге, без изменения глобального PATH.

## Фактическая проверка окружения

- Локальный Flutter 3.44.4 успешно запущен; Dart SDK 3.12.2 подтверждён отдельным запуском `dart --version`. Файлы SDK восстановлены из официального tag; рабочее дерево SDK чистое.
- `flutter --suppress-analytics pub get --enforce-lockfile` на неизменённом приложении завершился кодом 66: локальный `../vpn-service` отсутствует, разрешение зависимостей невозможно. Лог сохранён отдельно как `veilor-baseline-pub-get.log`.
- Исходные `lib`, `bind`, `windows`, `pubspec.yaml`, `pubspec.lock` и `third_party` после проверки не изменены. Заглушки отсутствующих файлов не создавались.
- Пользователь подтвердил, что располагает только публичным репозиторием и доступа к дополнительным исходникам нет. Это препятствие функциональной сборке на прежней реализации. Установка остальных инструментов его не устраняет.

До изменения требования о функциональной идентичности не выбирать другой VPN-движок/обвязку и не выдавать альтернативную реализацию за прежний Karing. Чистый Flutter-UI можно разрабатывать независимо, явно отделяя его от неподтверждённой VPN-реализации.

## Уточнение после исследования осуществимости

В истории Git найден commit `e3c19f1eb1225dbd48a4862f0983b82d0af8de69` от 7 мая 2025, содержащий старые версии **48 из 66** отсутствующих файлов. В их числе VPNService, SingboxConfigBuilder и ClashApi. Удаление этих файлов видно в `3c00ed6480b10eb3a9e7b702669dd917a4c9c65e`. Они извлечены отдельно как историческая справка и не восстановлены в активном `lib`.

Это улучшает возможность восстановления: не всю отсутствующую логику требуется исследовать по бинарным файлам. Но старые версии не равны текущим, пакет `vpn_service` остаётся отсутствующим, работоспособная исходная сборка не получена. Подробности, хеши и наблюдения локального API находятся в отчёте чата `outputs/veilor-feasibility/findings.md`.
